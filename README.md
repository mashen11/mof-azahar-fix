# Mirror of Fate 动作缺陷修复构建

基于 [Azahar 2126.2](https://github.com/azahar-emu/azahar) 的自建分支，修复《恶魔城：暗影之王 —
命运之镜》（`00040000000BAC00`）在部分地图段的**角色滑步**与**折腰**。

这不是官方 Azahar，是社区测试构建。**请先备份你的存档。**

---

## 症状

- 只在**某些地图段**出现，站着不动不出现；
- 走动或跑动时，角色上半身与下半身错位（折腰），脚底相对地面滑动；
- 向右移动比向左移动明显；
- 攻击、跳跃看起来正常。

## 根因

模拟器的 GPU 延迟模型按三角面数线性估算一次提交要花多久。它回答的是「这批几何有多贵」，
不是「一轮场景渲染要多久」。在三角面少的场景段它只算出 3–4 ms，而一帧是 16.7 ms。

游戏按渲染耗时给自己限速：看到还有九毫秒余量，就在同一帧里把整个场景再渲一遍。而这个标题
**不做双缓冲** —— 长时间统计里 `active_fb == shown_fb` 恒为 100%，显示缓冲从不翻转。于是第二遍
直接写进同一个可见缓冲，第一遍留下的深度值又挡住第二遍的一部分，屏幕上就留下两套骨骼的混合。

证据（PICA 命令流插桩）：受影响帧里角色被绘制 6 次而不是 3 次，两遍各写同样的 3 个渲染目标，
中间没有清屏，57 个骨骼槽位**全部**不同。

## 修法

1. **场景耗时下限 15 ms**（`DelayGenerator::MinSceneDelayNs`）：只对「画过角色的命令表」生效，
   且每条命令表最多收一次。一帧 16.7 ms，占满但不超时，访客就没余量开第二遍。
2. **GPU 延迟倍率 1.6**（编译期默认，`DelayScale`）：抵消模型里「GPU 比真机快一倍」的假设。

实测（同一存档、同一方向、各 6–7 秒）：

| 版本 | 左移双遍帧 | 右移双遍帧 | 帧率 |
|---|---|---|---|
| 修复前 | 22 / 240 | 1–11 / 240 | 58.1 |
| 修复后 | 8 / 240 | 0–1 / 240 | 58.4–58.7 |
| 掌机实测 | — | — | 满帧（16.7 ms 内，`ge12=0`） |

另外顺手修了一个即时存档的缺陷：自建构建存的存档在加载时被自己判成「不同版本」而拒绝。

## 下载

到本仓库的 **Releases** 页：

- `app-vanilla-relWithDebInfo.apk` —— 掌机（Android，arm64）
- `azahar-mof-fix-win64.zip` —— Windows 桌面端

## 安装

### 掌机

```bash
adb install -r app-vanilla-relWithDebInfo.apk
```

包名 `org.azahar_emu.azahar.debug`，覆盖安装会保留原有配置和游戏存档。

装好后进 **设置 → 图形**，确认：

| 项 | 值 |
|---|---|
| 图形 API | Vulkan |
| 限制帧率 | 开启，100 |
| 模拟 3DS GPU 时序 | **开启** |

前两项 `run_mof.bat` 那套配置已经写进默认值，但如果你之前装过旧版，`config.ini` 里的
`use_frame_limit` 可能被回写成 `false`，需要手动改回。

### Windows

解压后直接运行 `azahar.exe`。Qt 运行库已随包附带，不需要额外安装。

配置文件在 `%APPDATA%\azahar\`，与官方版共用同一目录 —— 如果两版交替使用，注意配置会互相覆盖。

## 已知问题

- **左移仍有约 3% 的帧**会出现双遍渲染，表现为「偶尔卡顿一下」。再往上加延迟能把这一项压到
  1–2%，但帧率会掉到 45，不值得。
- 时序参数是按这一个标题调的，**其它游戏未做验证**。如果你在其他游戏上发现掉帧，请反馈。
- 掌机端的渲染遍数统计没有移植过去，所以上面的数字来自桌面端，掌机只有帧率数据。
- 只支持 Vulkan 后端调优；OpenGL 后端未验证。

## 反馈

请到 Issues 提问，尽量带上：

1. 平台（Windows / 掌机型号）、图形 API；
2. 出问题的**地图位置**（哪个区域、附近有什么地标）；
3. **移动方向**，以及按住方向键后大约第几秒；
4. 截图或录屏（折腰在静态图里常常看不出来，录屏更有用）。
